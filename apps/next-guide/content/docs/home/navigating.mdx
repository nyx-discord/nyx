## Sections Overview

This guide is organized into three main sections: **Home**, **Use**, and **Extend**. Each section serves a specific type of reader and purpose.

If you're unsure where to start or what to skip, this page is here to help you find your path.

<Callout>Use the select menu between the Search bar and the section's pages to select the section you want to read.</Callout>

### Home — Understand the Framework

The **Home** section (you're here now) introduces the framework:

- What it is and what it's not
- Key design goals and support philosophy
- The two core packages (<CoreMention /> and <FrameworkMention />)
- How to navigate the rest of the guide (this page)

Use this section if you want to **understand the framework before committing** to it, or if you're figuring out **where to go next**.

---

### Use — Build with the Framework

The **Use** section is for developers who want to build bots using the framework’s default setup.

Start here if:
- You want to get a bot running as quickly as possible
- You don’t need to customize internal behavior
- You’re okay with using the default implementations provided in the <FrameworkMention /> package

Topics covered in this section include:
- Setting up your bot
- Registering commands, events, and components
- Using configuration and utilities provided out-of-the-box

Think of this as **using the framework as intended, without modifying its internals**.

---

### Extend — Customize and Inject

The **Extend** section is for advanced users who want to:
- Replace or override default behavior
- Inject their own services or logic into the framework
- Build on top of the core types and interfaces

Start here if:
- You want to implement custom logging, error handling, or command routing
- You need fine-grained control over the framework’s behavior
- You prefer composition over configuration

This section explores:
- The role of the <CoreMention /> package
- Dependency injection in detail
- Extending and swapping components using interfaces

You don’t need to *extend* the framework to use it — but if you *do* need to, it’s ready for it.

---

## Not sure where to go?

If you're unsure which path is for you:

- **Start with the [Use section](../use/index.mdx))** to get familiar with the framework.
- When you hit a limitation or want to improve a piece of logic, **jump into the [Extend section](../extend/index.mdx)**.

You can also mix and match — use defaults for most things, and override just one part.
