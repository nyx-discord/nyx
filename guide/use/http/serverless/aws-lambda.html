AWS Lambda

Run an HTTP bot on AWS Lambda with a function URL.

Reading time:2 min read

This page assumes you've read Serverless, and have a createBot() function like the one there.

Lambda has no waitUntil: it freezes the function as soon as the handler returns. The handler below waits for your handlers to finish before returning, so Discord gets its HTTP response only after your command is done.

Its reply still reaches Discord in time, since commands reply through the API, but keep commands short, and move slow work (anything after a defer that takes more than a few seconds) to a queue processed by another function.

Deploying

Deploy the function the way you prefer. Some ways to do it:

  • By hand: bundle with npx esbuild src/index.ts --bundle --platform=node --target=node22 --format=esm --outfile=dist/index.mjs, zip dist/index.mjs, and upload it on the AWS console. The handler is then index.handler.
  • AWS SAM: a function with BuildMethod: esbuild and a FunctionUrlConfig, deployed with sam build && sam deploy.
  • AWS CDK: a NodejsFunction, which bundles your TypeScript by itself, with addFunctionUrl().
  • Continuous deployment: run either of the above from your CI, like GitHub Actions with aws-actions/configure-aws-credentials, on every push. It's a good place to deploy your commands too.

Remember to deploy your commands whichever way you choose.

Setting the endpoint

On the Developer Portal, set your app's Interactions Endpoint URL to your function URL, and its Webhook Events URL (if you use them) to the same URL ending in /webhook-events.
