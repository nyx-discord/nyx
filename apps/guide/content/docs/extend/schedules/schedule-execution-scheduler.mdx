The <DocsLink pkg='framework' name='DefaultScheduleExecutionScheduler' decorated={false} /> is responsible for interpreting the schedule's interval (usually a cron string) and creating/managing the <DocsLink pkg='core' name='ScheduleJobAdapter' decorated={false} /> that will trigger execution.

It relies on the [`ScheduleJobAdapter`](/extend/schedules/schedule-job-adapter) to interface with the actual timing mechanism (e.g. `cron`), and the adapter is the one that waits for the scheduled time and invokes the execution.

## When to override

| ✅ Override if you want to... | ❌ Don't override if you want to... |
|---|---|
| Use a different timing library or job backend (e.g., not `cron`). | Just adjust the job adapter itself. Create a custom `ScheduleJobAdapter` instead. |
| Support a different interval format or next-run strategy (e.g., RRULE-like scheduling). | Change schedule execution logic (try/catch, retry, middleware behavior). That belongs to `ScheduleExecutor`. |
| Implement custom misfire/catch-up behavior for delayed or missed runs. | Change schedule persistence. That belongs to `ScheduleRepository`. |

## Overriding

<Steps>
<Step>
### Creation

Create a custom scheduler extending <DocsLink pkg='framework' name='DefaultScheduleExecutionScheduler' decorated={false} />.

```ts twoslash
import { DefaultScheduleExecutionScheduler } from '@nyx-discord/framework';

class MyScheduler extends DefaultScheduleExecutionScheduler {
  // Override internal methods
}
```

</Step>
<Step>
### Registration

Create it and set it to the [`ScheduleManager`](/extend/schedules/schedule-manager).

```ts twoslash
import type { NyxBot } from '@nyx-discord/framework';
declare const bot: NyxBot;
// ---cut---
import { DefaultScheduleExecutionScheduler } from '@nyx-discord/framework';

class MyScheduler extends DefaultScheduleExecutionScheduler {
  /** Your overrides */
}

bot.getScheduleManager().setScheduler(MyScheduler.create());
```

The <DocsLink pkg='framework' name='DefaultScheduleExecutionScheduler.create()' decorated={false} /> method instantiates your custom scheduler, not the default one.

</Step>
</Steps>
