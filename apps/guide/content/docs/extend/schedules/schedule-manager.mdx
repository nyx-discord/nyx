The `ScheduleManager` is the object that holds together the nyx schedule system. At a glance:

- Registration flow: when adding a schedule, stores it in the repository and then starts its runtime job in the scheduler.
- Failure safety: if schedule registration fails midway, rolls back repository state and scheduler job creation to stay consistent.
- Execution boundary: `tick` resolves a schedule by ID and executes it through the executor with populated metadata.
- Schedule events: emits manager-level `ScheduleAdd`/`ScheduleRemove` events and supports subscriptions for schedule lifecycle reactions.

In practice, this makes it the boundary where schedule persistence, job lifecycle, execution, and manager events are coordinated.

## Overriding

<Steps>
<Step>
### Creation
Create a custom schedule manager by either:

* Extending <DocsLink pkg='framework' name='DefaultScheduleManager' decorated={false} /> (<FrameworkMention />'s implementation, recommended for less work).
* Implementing <DocsLink pkg='framework' name='ScheduleManager' decorated={false} /> (<CoreMention />'s base definition).

```ts twoslash
import { DefaultScheduleManager } from '@nyx-discord/framework';

class MyScheduleManager extends DefaultScheduleManager {
  public myCustomPublicMethod() {
    return 'I work!' as const;
  }
}
```

</Step>
<Step>
### Registration

Then you can pass it to your bot:

```ts twoslash
import { Client } from 'discord.js';
import { DefaultScheduleManager } from '@nyx-discord/framework';

class MyScheduleManager extends DefaultScheduleManager {
  public myCustomPublicMethod() {
    return 'I work!' as const;
  }
}
// ---cut---
import { Bot, type NyxBot } from '@nyx-discord/framework';

const myBot = Bot.create((bot: NyxBot) => ({
  // ---cut-start---
  token: 'TOKEN',
  client: new Client({ intents: [] }),
  logger: console,
  deployCommands: true,
  // @ts-expect-error Incomplete example
  // ---cut-end---
  // ... other options
  scheduleManager: new MyScheduleManager(/** ... */),
}));

const manager = myBot.getScheduleManager();
const result = manager.myCustomPublicMethod();
//     ^?
```

The class is able to infer the type of your custom manager, so accessing any custom method or property will work without errors.

If you ever want to use this custom bot type with your injected manager somewhere else, you can do so via the generic:

```ts twoslash
import { Client } from 'discord.js';
import { DefaultScheduleManager } from '@nyx-discord/framework';
class MyScheduleManager extends DefaultScheduleManager {
  public myCustomPublicMethod() {
    return 'I work!' as const;
  }
}
// ---cut---
import type { NyxBot, InjectableBotDependencies } from '@nyx-discord/framework';

type BotWithCustomManager = NyxBot<InjectableBotDependencies & { scheduleManager: MyScheduleManager }>;

function functionOnlyForCustomManager(bot: BotWithCustomManager) {
  const manager = bot.getScheduleManager();
  const result = manager.myCustomPublicMethod();
  //     ^?
}
```

For readability purposes, we recommend storing the type with the generic in a separate type, like in the example.
