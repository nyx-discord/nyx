Command Internals

Reading time:3 min read

The commands system is made up of several components that work together to store, resolve, execute commands and more.

Command system components

Specifically, these components are:

  • CommandManager: The entry point for the command system, holding all the command-related objects and methods that use all of these objects. All objects below are contained here.
  • CommandResolver: Resolves the command that a given command interaction refers to.
  • CommandExecutor: Executes commands, checking its MiddlewareList and passing errors to the ErrorHandler.
  • CommandRepository: Stores all the currently registered commands.
  • CommandCustomIdCodec: De/serializes commands names to/from customId strings, for the Command Components feature.
  • CommandDeployer: Deploys commands to Discord and stores the ApplicationCommand mappings.
  • Command EventBus: An EventBus that emits command related events.
  • CommandSubscriptionsContainer: Stores the subscribers that are subscribed to the client's EventBus to listen for command interactions.

Diagram usage

  • You can zoom and drag on the diagrams.
  • A dashed step means it's executed through a non awaited (but caught) Promise, so the next one is inmediately executed if there's an I/O operation in the step.
  • You can hover over steps with (?) to see extra details.
  • If a step goes to a target, and that target doesn't continue the flow, then it's an immediate return, like a getter call.
