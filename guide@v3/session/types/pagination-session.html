Pagination Session

See in:
Reading time:4 min read
It's recommended to read the Session page first, all of its features apply to this.

A PaginationSession is a special type of session made to be paginated (have pages).

From a manager's perspective, a pagination session is just a regular session. The pagination logic happens inside the session itself.

Page switch

A page switch is triggered when the user sends an interaction to the pagination session, and a page can be extracted from it:

  1. It attempts to extract a referred page, depending on the interaction type:
    • Buttons: Extracts from the customId.
    • Select Menu: Extracts from the customId. If no page is present there, and it's a StringSelectMenu, and only one value was selected, it extracts from the selected value.
    • Modal: Extracts from the customId. If no page is present there, it iterates through the modal's components, searching for a component whose customId is the session's customId. If there is one, the page is extracted from said component's value.
  2. If there's no referred page, it behaves like a regular session, passing the interaction to the appropiate handler.
  3. If there's a referred page, it updates its currentPage and calls #updatePage().

Overriding page resolving

You can override this behavior by overriding extractPageFromInteraction(), or the more concrete methods:

  • extractPageFromButton() for buttons
  • extractPageFromSelectMenu() for select menus
  • extractPageFromModal() for modals

Pagination customId

The page to switch to is usually extracted from the customId. This means you'll need to change the way you build it in case you want to make a component that switches to a specific page.

You can add more ways by overriding extractPageFromButton().
