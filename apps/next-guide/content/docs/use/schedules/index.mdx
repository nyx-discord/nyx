`Schedules` are objects that are ticked some time in the future, and can be used as a feature complete way of scheduling events in your bot, apart from Node's `setInterval()` API.

In essence, a `Schedule` object contains its ticking logic and its interval of when it wishes to be executed, which can be in [cron](https://crontab.guru/) format, in an amount of ms (`number`), or as a `Date`.

## Quick example

Let's create a schedule that updates the activity with the member count every half hour:

```ts twoslash
import { type NyxBot } from '@nyx-discord/framework';
declare const bot: NyxBot;
// ---cut---
import { AbstractSchedule, TypedFields, type MetaCollection } from '@nyx-discord/framework';

class MemberCountSchedule extends AbstractSchedule {
  protected readonly interval = '*/30 * * * *';

  public async tick(meta: MetaCollection) {
    const bot = TypedFields.Bot.get(meta, true);
    const client = bot.getClient();
    if (!client.user) return;

    const memberCount = client.guilds.cache.reduce((acc, guild) => acc + guild.memberCount, 0);
    await client.user.setActivity(`Members: ${memberCount}`);
  }
}

await bot.getScheduleManager().addSchedule(new MemberCountSchedule());
```

Given it uses the provided metadata, it'll work even if the same instance is used across multiple bots.

## Schedule Job

When a schedule is added, a job will be created for it, which is responsible for notifying the framework when it is time to run it.
It's a wrapper over a more "lower-level" component that will actually do the ticking, like a cron object, a Node interval, etc.

<Callout>
  How the job is created is entirely customizable, but by default, the [cron npm package](https://www.npmjs.com/package/cron) is used.
</Callout>

There are multiple ways to get it, but given a schedule itself does not depend on a bot, you'll always need the bot:

```ts twoslash
import type { NyxBot, Schedule } from '@nyx-discord/framework';
declare const bot: NyxBot;
declare const schedule: Schedule;
// ---cut---
const fromScheduler = bot.getScheduleManager().getScheduler().getJobForSchedule(schedule);
const fromSchedule = schedule.getJob(bot);
const whenBeingAdded = await bot.getScheduleManager().addSchedule(schedule);
```

It's the entry point for interacting with the schedule's ticking logic, and can be used to pause or resume it externally.

```ts twoslash
import type { UndestroyableScheduleJobAdapter } from '@nyx-discord/framework';
declare const job: UndestroyableScheduleJobAdapter<unknown>;
// ---cut---
await job.pause();
await job.resume();

// Currently would be `CronJob` from the cron package
const rawTicker = job.getRaw();
```

## Registration notification

The schedule will be notified when it's un/registered from a bot:

```ts twoslash
import type { NyxBot, Schedule } from '@nyx-discord/framework';
declare const bot: NyxBot;
// ---cut---
import { AbstractSchedule } from '@nyx-discord/framework';

// ---cut-start---
// @ts-expect-error Incomplete example
// ---cut-end---
class MySchedule extends AbstractSchedule {
  public onRegister(bot: NyxBot) {
    bot.getLogger().log('My schedule has been registered!');
  }

  public onUnregister(bot: NyxBot) {
    bot.getLogger().log('My schedule has been unregistered!');
  }
}

const schedule = new MySchedule();
await bot.getScheduleManager().addSchedule(schedule);
// console: My schedule has been registered!
await bot.getScheduleManager().removeSchedule(schedule);
// console: My schedule has been unregistered!
```

## Metadata

When extending nyx with plugins, you may want to specify extra data for them. You can do so with the `MetaCollection` object, saved on the schedule.

<Callout>
While schedules internally save a `MetaCollection`, the return type of `#getMeta()` is a `ReadonlyMetaCollection`,
meaning that external objects can read the collection, but not modify it.
</Callout>

```ts twoslash
import { AbstractSchedule, Identifier } from '@nyx-discord/framework';
import { Collection } from 'discord.js';

// ---cut-start---
// @ts-expect-error Incomplete example
// ---cut-end---
class MySchedule extends AbstractSchedule {
  protected readonly meta = new Collection<Identifier, unknown>([
    ['someKey', 'someValue']
  ]);
}

const schedule = new MySchedule();
const meta = schedule.getMeta();
const value = meta.get('someKey'); // 'someValue'
```

For a more type-safe approach, you can use `TypedFields`. Check the [Metadata](/use/other/meta) page for more information.
