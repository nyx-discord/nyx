A `PaginationSession` is a special type of session made to be paginated (have pages).

From a manager's perspective, a pagination session is just a regular session. The pagination logic happens inside the session
itself.

## Page switch

A page switch is triggered when the user sends an interaction to the pagination session, and a page can be extracted from it:

<ol>
  <li>It attempts to extract a referred page, depending on the interaction type:<ul><li>Buttons: Extracts from the customId.</li><li>Select Menu: Extracts from the customId. If no page is present there, and it's a `StringSelectMenu`, and only one value was selected, it extracts from the selected value.</li><li>Modal: Extracts from the customId. If no page is present there, it iterates through the modal's components, searching for a component whose `customId` is the session's `customId`. If there is one, the page is extracted from said component's value.</li></ul></li>
  <li>If there's no referred page, it behaves like a regular session, passing the interaction to the appropiate handler.</li>
  <li>If there's a referred page, it updates its `currentPage` and calls `#updatePage()`.</li>
</ol>

<Callout title ="Overriding page resolving">
You can override this behavior by overriding `extractPageFromInteraction()`, or the more concrete methods:
- `extractPageFromButton()` for buttons
- `extractPageFromSelectMenu()` for select menus
- `extractPageFromModal()` for modals
</Callout>

### Implementation

Apart from the base `Session` implementation, also implement the `updatePage()` method:

<Tabs items={['discord.js', '@discordjs/core']}>
  <Tab>
```ts twoslash
import { AbstractPaginationSession, type DjsSessionUpdateInteraction } from '@nyx-discord/plugin-sessions/djs';

// ---cut-start---
class MyPaginationSession extends AbstractPaginationSession<void> {
  public async onStart() {}
  public async onEnd() {}
// ---cut-end---
  protected async updatePage(interaction: DjsSessionUpdateInteraction): Promise<boolean> {
    if ('update' in interaction) {
      await interaction.update({ content: `Page: ${this.currentPage}` });
    }
    return true;
  }
}
```
  </Tab>
  <Tab>
```ts twoslash
import { AbstractPaginationSession, type CoreSessionUpdateInteraction } from '@nyx-discord/plugin-sessions/djs-core';

// ---cut-start---
class MyPaginationSession extends AbstractPaginationSession<void> {
  public async onStart() {}
  public async onEnd() {}
// ---cut-end---
  protected async updatePage(interaction: CoreSessionUpdateInteraction): Promise<boolean> {
    await interaction.api.interactions.updateMessage(interaction.data.id, interaction.data.token, {
      content: `Page: ${this.currentPage}`,
    });
    return true;
  }
}
```
  </Tab>
</Tabs>

Similarly to `update()`, it must return whether the session's TTL should be renewed or not.

</Step>

### Initialization

Instantiate and start your session the same way as a regular one:

<Tabs items={['discord.js', '@discordjs/core']}>

// ---cut-start---
import type { NyxBot } from '@nyx-discord/djs';
import { AbstractPaginationSession, type DjsSessionStartInteraction } from '@nyx-discord/plugin-sessions/djs';

class MyPaginationSession extends AbstractPaginationSession<void> {
  public async onStart() {}
  public async onEnd() {}
  protected async updatePage() { return true; }

declare const interaction: DjsSessionStartInteraction;
declare const bot: NyxBot;
const sessionId = 'mySessionId';

const session = new MyPaginationSession({ bot, id: sessionId, startInteraction: interaction });

## Pagination customId

The page to switch to is usually extracted from the customId. This means you'll need to change the way you build it in case you want to make a component that switches to a specific page.

<Tabs items={['Button', 'Select Menu', 'Modal']}>
<Tab>

<Tabs items={['discord.js', '@discordjs/core']}>
  <Tab>
```ts twoslash
import { ButtonBuilder } from 'discord.js';
import { AbstractPaginationSession } from '@nyx-discord/plugin-sessions/djs';

// @ts-expect-error Incomplete example
class MyPaginationSession extends AbstractPaginationSession<void> {
  public async start() {
// ---cut---
// For a specific page
const buttonId = this.buildPageCustomId(3);
const pageThreeButton = new ButtonBuilder()
  .setCustomId(buttonId)
  .setLabel('Go to page 3');

// For the next page
const nextPageButtonId = this.buildPageCustomId(this.currentPage + 1);
const nextPageButton = new ButtonBuilder()
  .setCustomId(nextPageButtonId)
  .setLabel('Next page');
// ---cut-after---
  }
}
```
  </Tab>

<Tab>

You can either:

* Put the pagination custom id in the select menu itself, making it switch to that page regardless of selection.

```ts twoslash
  import { SelectMenuBuilder, StringSelectMenuOptionBuilder } from 'discord.js';
  import { AbstractPaginationSession } from '@nyx-discord/plugin-sessions/djs';

  // @ts-expect-error Incomplete example
  class MyPaginationSession extends AbstractPaginationSession<void> {
    public async start() {
  // ---cut---
  const selectId = this.buildPageCustomId(3);
  const select = new SelectMenuBuilder()
    .setCustomId(selectId)
    .setPlaceholder('Switch to page 3')
  // ---cut-after---
    }
  }
```

* Put the pagination custom id in the select menu's options, making it switch to that page only when the option is selected.
  Note that you still need to put the session's custom id in the select menu itself.

```ts twoslash
  import { StringSelectMenuBuilder, StringSelectMenuOptionBuilder } from 'discord.js';
  import { AbstractPaginationSession } from '@nyx-discord/plugin-sessions/djs';

  // @ts-expect-error Incomplete example
  class MyPaginationSession extends AbstractPaginationSession<void> {
    public async start() {
  // ---cut---
  const selectId = this.buildCustomId();
  const select = new StringSelectMenuBuilder()
    .setPlaceholder('Go to page...')
    .setCustomId(selectId)
    .addOptions([
      new StringSelectMenuOptionBuilder()
        .setLabel('1')
        .setValue(this.buildPageCustomId(1)),
      new StringSelectMenuOptionBuilder()
        .setLabel('2')
        .setValue(this.buildPageCustomId(2)),
    ]);
  // ---cut-after---
    }
  }
```

You can add more ways by overriding `extractPageFromSelectMenu()`.

</Tab>
<Tab>

You can either:

* Put the pagination custom id in the modal itself, making it switch to that page regardless of values.

```ts twoslash
  import { ModalBuilder, TextInputBuilder } from 'discord.js';
  import { AbstractPaginationSession } from '@nyx-discord/plugin-sessions/djs';

  // @ts-expect-error Incomplete example
  class MyPaginationSession extends AbstractPaginationSession<void> {
    public async start() {
  // ---cut---
  const modalId = this.buildPageCustomId(3);
  const modal = new ModalBuilder()
    // highlight-next-line
    .setCustomId(modalId)
    .setTitle('A modal that switches to page 3');
  // ---cut-after---
    }
  }
```

* Put the session's custom id in the modal's components, making it switch to that component's value (if it's a number).
  Note that you still need to put the session's custom id in the modal.

  <Callout type="warn">If the component's value is not a number, it will be handled as a regular update (`handleModal()`).</Callout>

```ts twoslash
  import { ModalBuilder, TextInputBuilder, ActionRowBuilder } from 'discord.js';
  import { AbstractPaginationSession } from '@nyx-discord/plugin-sessions/djs';

  // @ts-expect-error Incomplete example
  class MyPaginationSession extends AbstractPaginationSession<void> {
    public async start() {
  // ---cut---
  const customId = this.buildCustomId();
  const modal = new ModalBuilder()
    .setCustomId(customId)
    .setTitle('Type a page number')
    .addComponents(new ActionRowBuilder<TextInputBuilder>().addComponents(
      new TextInputBuilder().setCustomId(customId)
        .setLabel('Page')
    ));
  // ---cut-after---
    }
  }
```
