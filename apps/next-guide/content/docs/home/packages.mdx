## Structure

The framework is built with two packages: `@nyx-discord/core` and `@nyx-discord/framework`, abbreviated in this guide as <CoreMention /> and <FrameworkMention />:

| Core                                                                                        | Framework                                                                                                                                                       |
|---------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Defines all the object templates (interfaces) and their relations, acting as the blueprint. | Provides default, minimal implementations for <CoreMention />, making it directly usable.                                                                       |
| Minimal runtime dependencies (since it doesn't have much actual code).                      | Its implementations are designed to depend on interfaces from <CoreMention />, rather than each other, making those dependencies fully replaceable by your own. |
| It doesn't have any implementations, so it's not usable by itself.                          | Low runtime dependencies due to its "bare bones" ideology.                                                                                                      |

## Which package to use?

Most of the time, you'll want to use <FrameworkMention />. Even if you want to include your own components, this library makes it easy to replace them via constructor injection.

If you want to develop something for nyx, such as a plugin, you can use <CoreMention />. This way, you can depend on the interfaces and not any actual implementations, ensuring your component will work across all nyx implementations.
