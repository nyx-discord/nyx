Filters are objects or callbacks that can restrict the execution of a given subscriber.

They receive all the information about the subscriber, the event arguments that triggered it, and the execution metadata, and return a boolean indicating whether the subscriber should be executed or not.

## Usage

<Steps>
<Step>

### Creation

Either:

- Create a class that extends `AbstractEventSubscriberFilter` and implements the `check()` method.
 ```ts twoslash
 type MyEventsArgs = {
   someEvent: [string, number];
 };
 // ---cut---
 import { AbstractEventSubscriberFilter } from '@nyx-discord/framework';
 import type { EventSubscriber, MetaCollection } from '@nyx-discord/framework';

 class MyFilter extends AbstractEventSubscriberFilter<MyEventsArgs, 'someEvent'> {
   public async check(
     subscriber: EventSubscriber<MyEventsArgs>,
     meta: MetaCollection,
     ...args: MyEventsArgs['someEvent']
   ): Promise<boolean> {
     // Do some checks
     return true; // or false if the subscriber should not be executed
   }
 }
 ```

- Create a function that returns a boolean or a Promise that resolves to a boolean.
 ```ts twoslash
 type MyEventsArgs = {
   someEvent: [string, number];
 };
 // ---cut---
 import { type EventSubscriberFilterResolvable } from '@nyx-discord/framework';

 const myFilter: EventSubscriberFilterResolvable<
   MyEventsArgs,
   'someEvent'
 > = async (subscriber, meta, ...args) => {
   // Do some checks
   return true; // or false if the subscriber should not be executed
 };
 ```

<Callout title="Generic filter">
  You can also write a filter that will work regardless of the event being handled, by omitting the event name in the type arguments:

  ```ts twoslash
import { AbstractEventSubscriberFilter, type EventSubscriberFilterResolvable, type MetaCollection, type EventSubscriber } from '@nyx-discord/framework';
// ---cut---
  type MyEventsArgs = {
    someEvent: [string, number];
    otherEvent: [boolean];
  };

  class MyFilter extends AbstractEventSubscriberFilter<MyEventsArgs> {
// ---cut-start---
// @ts-expect-error Incomplete example
// ---cut-end---
    public async check(
      subscriber: EventSubscriber<MyEventsArgs>,
      meta: MetaCollection,
      ...args: MyEventsArgs[keyof MyEventsArgs]
      // ^?
    ) { /** ... */ }
  }

// ---cut-start---
// @ts-expect-error Incomplete example
// ---cut-end---
  const myFilter: EventSubscriberFilterResolvable<MyEventsArgs> = async (
    subscriber,
    ...args
  //   ^?
  ) => { /** ... */ };
  ```

  Notice how `args` is a union of the possible event arguments for any event in the `MyEventsArgs` type.
</Callout>

</Step>

### Filter usage

Override the `filter` property in your subscriber:

- If you created a class, instantiate it:

```ts twoslash
import { AbstractEventSubscriber } from '@nyx-discord/framework';

// ---cut-start---
type MyEventsArgs = {
  someEvent: [string, number];
};
import { AbstractEventSubscriberFilter } from '@nyx-discord/framework';
// @ts-expect-error Incomplete example
class MyFilter extends AbstractEventSubscriberFilter<MyEventsArgs, 'someEvent'> {}
// @ts-expect-error Incomplete example
// ---cut-end---
class MySubscriber extends AbstractEventSubscriber<MyEventsArgs, 'someEvent'> {
  protected override readonly filter = new MyFilter();
}
```

- If you created a function, assign it directly:

```ts twoslash
import { AbstractEventSubscriber } from '@nyx-discord/framework';

// ---cut-start---
import { type EventSubscriberFilterResolvable } from '@nyx-discord/framework';
type MyEventsArgs = {
  someEvent: [string, number];
};
declare const myFilter: EventSubscriberFilterResolvable<MyEventsArgs, 'someEvent'>;
// @ts-expect-error Incomplete example
// ---cut-end---
class MySubscriber extends AbstractEventSubscriber<MyEventsArgs, 'someEvent'> {
  protected override readonly filter = myFilter;
}
```

Or use a simple arrow function directly:

```ts twoslash
import { AbstractEventSubscriber } from '@nyx-discord/framework';

// ---cut-start---
type MyEventsArgs = {
  someEvent: [string, number];
};
// @ts-expect-error Incomplete example
// ---cut-end---
class MySubscriber extends AbstractEventSubscriber<MyEventsArgs, 'someEvent'> {
  protected override readonly filter = () => {
    // Do some checks
    return true;
  };
}
```

## Wrapping/Merging Filters

The framework has some utility filters that wrap or merge others, allowing you to create complex filters by combining simpler ones.

<Callout>These wrappers work "synchronously", meaning that it'll wait for each filter, in the order they were passed, before checking whether to proceed to the next.</Callout>

- `AndFilter`: Combines multiple filters and only allows the subscriber to execute if all filters return `true`.
```ts twoslash
import { AndFilter, AbstractEventSubscriber } from '@nyx-discord/framework';

// ---cut-start---
import { type EventSubscriberFilterResolvable } from '@nyx-discord/framework';
type MyEventsArgs = {
  someEvent: [string, number];
};
declare const filter1: EventSubscriberFilterResolvable<MyEventsArgs, 'someEvent'>;
declare const filter2: EventSubscriberFilterResolvable<MyEventsArgs, 'someEvent'>;
// @ts-expect-error Incomplete example
// ---cut-end---
class MySubscriber extends AbstractEventSubscriber<MyEventsArgs, 'someEvent'> {
  protected override readonly filter = new AndFilter(filter1, filter2);
}
```

- `OrFilter`: Combines multiple filters and allows the subscriber to execute if at least one filter returns `true`.
```ts twoslash
import { OrFilter, AbstractEventSubscriber } from '@nyx-discord/framework';

// ---cut-start---
import { type EventSubscriberFilterResolvable } from '@nyx-discord/framework';
type MyEventsArgs = {
  someEvent: [string, number];
};
declare const filter1: EventSubscriberFilterResolvable<MyEventsArgs, 'someEvent'>;
declare const filter2: EventSubscriberFilterResolvable<MyEventsArgs, 'someEvent'>;
// @ts-expect-error Incomplete example
// ---cut-end---
class MySubscriber extends AbstractEventSubscriber<MyEventsArgs, 'someEvent'> {
  protected override readonly filter = new OrFilter(filter1, filter2);
}
```

- `NotFilter`: Inverts the result of a single filter, allowing the subscriber to execute if the filter returns `false`.
```ts twoslash
import { NotFilter, AbstractEventSubscriber } from '@nyx-discord/framework';
// ---cut-start---
import { type EventSubscriberFilterResolvable } from '@nyx-discord/framework';
type MyEventsArgs = {
  someEvent: [string, number];
};
declare const negatedFilter: EventSubscriberFilterResolvable<MyEventsArgs, 'someEvent'>;
// ---cut-end---

// ---cut-start---
// @ts-expect-error Incomplete example
// ---cut-end---
class MySubscriber extends AbstractEventSubscriber<MyEventsArgs, 'someEvent'>{
  // Will only execute if negatedFilter returns false
  protected override readonly filter = new NotFilter(negatedFilter);
}
```
