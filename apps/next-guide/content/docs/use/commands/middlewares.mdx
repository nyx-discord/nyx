Middlewares are objects or callbacks that run before any command is executed. They can do some pre-processing logic and store it in the metadata, or even prevent the command from being executed.

We will review some concepts before going into the usage.

## Priorities

Middlewares have a priority that determines the order in which they are executed:

- Higher priorities are executed first.
- Monitors are specifically meant for monitoring (e.g. metrics), though that's not enforced.
  - `HighMonitor` is the first priority to be executed.
  - `LowMonitor` is the last priority to be executed.

```ts twoslash
import { PriorityEnum } from '@nyx-discord/framework';

// @noErrors
PriorityEnum.
//           ^|
```

The default priority is `Normal`, it's changed by overriding the `priority` property in classes. It can't be changed for callback-based middlewares.

## Responses

A middleware returns a `MiddlewareResponse` that indicates whether it passes, forces to pass, or fails. If a middleware fails, the command will not be executed.

Use the utility methods from `AbstractCommandMiddleware` to create the response:
- `true()` - The middleware passes, and the command will be executed.
- `false()` - The middleware fails, and the command will not be executed.
- `forceTrue()` - The middleware forces the command to pass, even if other later middlewares would fail.

```ts twoslash
import { AbstractCommandMiddleware } from '@nyx-discord/framework';

class MyMiddleware extends AbstractCommandMiddleware {
  public async check() {
    // Do some checks
    return this.true(); // or this.false() or this.forceTrue()
  }
}
```

If you're using a callback-based middleware, you'll need to create your response manually.

## Usage

<Steps>
<Step>

### Creation

Either:
- Create a class that extends `AbstractCommandMiddleware` and implements the `check()` method.
```ts twoslash
import { AbstractCommandMiddleware } from '@nyx-discord/framework';
import type { AnyExecutableCommand, CommandResolvableInteraction, MetaCollection, MiddlewareResponse } from '@nyx-discord/framework';

class MyMiddleware extends AbstractCommandMiddleware {
  public async check(
    command: AnyExecutableCommand,
    interaction: CommandResolvableInteraction,
    meta: MetaCollection
  ): Promise<MiddlewareResponse> {
    // Do some pre-processing logic
    return this.true();
  }
}
```

- Create a function that returns a `MiddlewareResponse`.
```ts twoslash
import { type CommandMiddlewareResolvable, MiddlewareResponse } from '@nyx-discord/framework';

const myCallbackMiddleware: CommandMiddlewareResolvable = async (command, interaction, meta) => {
  // Do some pre-processing logic
  return {
    allowed: true,
    checkNext: true,
  };
};
```

</Step>
<Step>

### Registration

Register it to the executor's `MiddlewareList`:

```ts twoslash
import type { NyxBot, AbstractCommandMiddleware, CommandMiddlewareResolvable } from '@nyx-discord/framework';
declare const MyMiddleware: new () => AbstractCommandMiddleware;
declare const myCallbackMiddleware: CommandMiddlewareResolvable;
declare const bot: NyxBot;
// ---cut---
bot.getCommandManager().getExecutor().getMiddleware().add(new MyMiddleware(), myCallbackMiddleware);
```

</Step>
</Steps>

## Examples

### Logging middleware

```ts twoslash
import { AbstractCommandMiddleware } from '@nyx-discord/framework';
import type { AnyExecutableCommand, CommandResolvableInteraction, MetaCollection } from '@nyx-discord/framework';

class LoggingMiddleware extends AbstractCommandMiddleware {
  public async check(
    command: AnyExecutableCommand,
    interaction: CommandResolvableInteraction,
    meta: MetaCollection
  ) {
    console.log(`User ${interaction.user.tag} is executing command ${command.getData().name}`);
    return this.true();
  }
}
```
