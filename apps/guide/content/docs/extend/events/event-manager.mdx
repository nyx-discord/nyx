The `EventManager` is the object that holds together the nyx event system. At a glance:

- Core buses: owns two foundational buses, a `managerBus` (internal manager lifecycle events) and a `clientBus` (Discord client events).
- Safety guard: protects both core buses in the constructor so manager APIs cannot remove them by accident.
- Bus registry: stores every additional bus in one registry for lookup, addition, and removal.
- Manager events: emits manager-level events when buses are added or removed, enabling reactions to bus lifecycle changes.

In practice, this makes it the boundary where bus creation, registration, lifecycle, and lookup are coordinated.

## Overriding

<Steps>
<Step>
### Creation
Create a custom event manager by either:

* Extending `DefaultEventManager` from <FrameworkMention />.
* Implementing `EventManager` from <CoreMention />.

```ts twoslash
import { DefaultEventManager } from '@nyx-discord/framework';

class MyEventManager extends DefaultEventManager {
  public static create(...args: Parameters<typeof DefaultEventManager.create>) {
    return super.create(...args) as MyEventManager;
  }

  public myCustomPublicMethod() {
    return 'I work!' as const;
  }
}
```

</Step>
<Step>
### Registration

Then you can pass it to your bot:

```ts twoslash
import { Client } from 'discord.js';
import { DefaultCommandManager, DefaultEventManager } from '@nyx-discord/framework';

class MyEventManager extends DefaultEventManager {
  public myCustomPublicMethod() {
    return 'I work!' as const;
  }
}
// ---cut---
import { Bot, type NyxBot } from '@nyx-discord/framework';

const myBot = Bot.create((bot: NyxBot) => {
  return {
    // ---cut-start---
    token: 'TOKEN',
    client: new Client({ intents: [] }),
    logger: console,
    deployCommands: true,
    // @ts-expect-error Incomplete example
    // ---cut-end---
    // ... other options
    eventManager: new MyEventManager(/** ... */),
  };
});

const manager = myBot.getEventManager();
const result = manager.myCustomPublicMethod();
//     ^?
```

The class is able to infer the type of your custom manager, so accessing any custom method or property will work without errors.

If you ever want to use this custom bot type with your injected manager somewhere else, you can do so via the generic:

```ts twoslash
import { DefaultEventManager } from '@nyx-discord/framework';
class MyEventManager extends DefaultEventManager {
  public static create(...args: Parameters<typeof DefaultEventManager.create>) {
    return super.create(...args) as MyEventManager;
  }

  public myCustomPublicMethod() {
    return 'I work!' as const;
  }
}
// ---cut---
import type { InjectableBotDependencies, NyxBot } from '@nyx-discord/framework';

type BotWithCustomManager = NyxBot<InjectableBotDependencies & { eventManager: MyEventManager }>;

function functionOnlyForCustomManager(bot: BotWithCustomManager) {
  const manager = bot.getEventManager();
  const result = manager.myCustomPublicMethod();
  //     ^?
}
```

For readability purposes, we recommend storing the type with the generic in a separate type, like in the example.

</Step>
</Steps>
