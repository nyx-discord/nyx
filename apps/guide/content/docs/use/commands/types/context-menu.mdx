Context menu commands are commands executed on special menus. Currently Discord has two types of context menus:

* [Message Context Menus](https://discord.com/developers/docs/interactions/application-commands#message-commands), shown when right clicking on a message.
* [User Context Menus](https://discord.com/developers/docs/interactions/application-commands#user-commands), shown when right clicking on a user.

## Creation

<Step>
### Implementation

Implement `data` that stores the command's data, and the respective `executeX()` method:

- `executeMessage()` for message context menus.
- `executeUser()` for user context menus.

<Tabs items={['discord.js', '@discordjs/core']}>
  <Tab>
    ```ts twoslash
    import { ApplicationCommandType, ContextMenuCommandBuilder, type MessageContextMenuCommandInteraction } from 'discord.js';
    import { AbstractContextMenuCommand } from '@nyx-discord/djs';

    class MyContextMenuCommand extends AbstractContextMenuCommand {
      protected readonly data = new ContextMenuCommandBuilder()
        .setName('My Context Menu')
        .setType(ApplicationCommandType.User) // or ApplicationCommandType.Message
        .toJSON();

      public async executeMessage(interaction: MessageContextMenuCommandInteraction) {
        await interaction.reply('Hello!');
      }
    }
    ```
  </Tab>
  <Tab>
    ```ts twoslash
    import { ApplicationCommandType } from '@discordjs/core';
    import type { APIMessageApplicationCommandInteraction, ToEventProps } from '@discordjs/core';
    import { AbstractContextMenuCommand } from '@nyx-discord/djs-core';

    class MyContextMenuCommand extends AbstractContextMenuCommand {
      protected readonly data = {
        name: 'My Context Menu',
        type: ApplicationCommandType.User, // or ApplicationCommandType.Message
      } as const;

      public async executeMessage(interaction: ToEventProps<APIMessageApplicationCommandInteraction>) {
        await interaction.api.interactions.reply(
          interaction.data.id,
          interaction.data.token,
          { content: 'Hello!' },
        );
      }
    }
    ```
  </Tab>
</Tabs>

</Step>

## Guild deployment

By default, all commands will be deployed in the global scope. If you want to deploy them in a specific guild, you can do so by implementing the `getGuilds()` method.

<Tabs items={['discord.js', '@discordjs/core']}>
  <Tab>
    ```ts twoslash
import { AbstractContextMenuCommand } from '@nyx-discord/djs';

// ---cut-start---
// @ts-expect-error Incomplete example
// ---cut-end---
class MyCommand extends AbstractContextMenuCommand {
  public getGuilds() {
    return ['GUILD_ID', 'ANOTHER_GUILD_ID'];
  }
}
```
  </Tab>

## Execution Meta

The second argument of the execute methods is a `Metadata` object, which is a `Record` that stores metadata about the command call.

Apart from the keys saved by the caller or the middleware, the dispatch meta contains:

* The execution ID, via the `TypedFields.Id` field.
* The execution start date, via the `TypedFields.CreationDate` field.
* The bot whose `Client` sent the interaction, via the `TypedFields.Bot` field.

To learn more about TypedFields, check the [Metadata](/use/other/meta) page.

## Metadata

When extending nyx with plugins, you may want to specify extra data for them. You can do so with the `Metadata` object, saved on the command.

<Callout>
While commands internally save a `Metadata`, the return type of `#getMeta()` is a `ReadonlyMetadata`,
meaning that external objects can read the object, but not modify it.
</Callout>

<Tabs items={['discord.js', '@discordjs/core']}>
  <Tab>
    ```ts twoslash
import { AbstractContextMenuCommand } from '@nyx-discord/djs';

// ---cut-start---
// @ts-expect-error Incomplete example
// ---cut-end---
class MyCommand extends AbstractContextMenuCommand {
  protected override readonly meta = {
    someKey: 'someValue',
  };
}

const command = new MyCommand();
const meta = command.getMeta();
const value = meta['someKey']; // 'someValue'
```
  </Tab>
  <Tab>
