## First Start

A minimum version of Node.js 18 is required to run, though we recommend latest LTS.

<Callout type="warn">Although they should work, nyx is not tested on Deno or Bun.</Callout>

We also recommend using a formatter like [Prettier](https://www.prettier.io/) and a linter like [ESLint](https://eslint.org/) or [TypeScript ESLint](https://typescript-eslint.io/).

<Steps>
<Step>

### Installing

```npm
npm i @nyx-discord/framework
```

You'll also need to install `discord.js` if you haven't already:

```npm
npm i discord.js
```

</Step>
<Step>

### Instantiating a Bot

You'll need a Discord.js `Client`. This can be any client, as long as it's not logged in or destroyed:

```ts twoslash
import { Client, GatewayIntentBits } from 'discord.js';

const client = new Client({ intents: [GatewayIntentBits.Guilds] });
```

Next up, we'll create a new instance of `Bot`. This is the main entry point of the framework, and it will handle the lifecycle
of your bot, including loading commands, managing events, and more.

<Callout>There's no global state, so you can create multiple bots and they'll all work independently with no issues!</Callout>

Create one with `Bot.create()`, which takes a function that gets passed the currently constructing bot
instance, and should return the options that you want for the bot.

```ts twoslash
import { Bot, type NyxBot } from '@nyx-discord/framework';
// ---cut-start---
import { Client, GatewayIntentBits } from 'discord.js';
declare const client: Client<boolean>;
// ---cut-end---

const myBot = Bot.create((bot: NyxBot) => ({
  token: 'TOKEN',
  client,
  logger: console, // Can be your own logger
  deployCommands: true, // Whether to deploy commands to Discord on start
}));
```

<Accordions type="single">
  <Accordion title={<p>About <code>new Bot()</code></p>}>
    You can also instantiate with the [`new`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/new) operator, but in order to allow dependency
    injection, this constructor requires every manager on its options, including default ones.

    You would need to instantiate and pass every manager to it:

    ```ts twoslash
    import { Client, GatewayIntentBits } from 'discord.js';
    declare const client: Client<boolean>;
    // ---cut---
    import { Bot, DefaultEventManager, DefaultPluginManager } from '@nyx-discord/framework';

    // ---cut-start---
    // @ts-expect-error Other managers missing for brevity
    // ---cut-end---
    const myBot = new Bot((bot) => ({
      token: 'TOKEN',
      client,
      logger: console,
      deployCommands: true,

      events: DefaultEventManager.create(bot, client),
      plugins: DefaultPluginManager.create(bot),
      // and so on
    }));
    ```

    You'll find this pattern in other `@framework` objects, where you can use either
    `new Object(depA, ...)` specifying every dependency, or `Object.create()` which uses default dependencies, and you can
    optionally inject your own to that method (while still keeping other defaults).
</Accordion>
</Accordions>

</Step>
<Step>

### Starting the Bot

Finally, to start it, simply call `.start()`. This will log in the client, set up event listeners, and get everything ready:

```ts twoslash
import { Bot } from '@nyx-discord/framework';
import { Client, GatewayIntentBits } from 'discord.js';
declare const client: Client;
declare const myBot: Bot;
// ---cut---
await myBot.start();
```

<Callout type="warn">
  If the start errors, it'll reject the promise, and the bot will enter in a `BotStatusEnum.Killed` state, meaning it won't
  be able to be used anymore. You can create a new bot instance and start it again, but you cannot recover the previous one.

  To get a bot's status at any time, you can use `Bot#getStatus()`.
</Callout>

</Step>
